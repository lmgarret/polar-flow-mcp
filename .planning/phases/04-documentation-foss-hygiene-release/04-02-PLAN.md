<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → GHCR | Workflow pushes Docker images using `GITHUB_TOKEN` scoped to repo |
| GitHub Actions runner → gh-pages branch | docs.yml pushes static site via `mkdocs gh-deploy` using `GITHUB_TOKEN` |
| GitHub Actions runner → main branch | release.yml commits CHANGELOG.md back to main using `GITHUB_TOKEN` |
| Third-party actions (orhun/git-cliff-action, softprops/action-gh-release) | Pinned by major version tag; supply-chain trust boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | E | release.yml `permissions:` block | mitigate | Scope to `contents: write` + `packages: write` only (not `write-all`); use `GITHUB_TOKEN` not PAT (RESEARCH.md Security Domain) |
| T-04-02-02 | T | Third-party actions (`orhun/git-cliff-action@v4`, `softprops/action-gh-release@v3`) | accept | Pinned by major version tag (acceptable per RESEARCH.md for a personal project); SHA pinning is a later hardening step |
| T-04-02-03 | T | Docker image content via build-push-action | mitigate | `context: .` builds from the committed repo tree at the tagged commit; tag is signed by the human releaser via git tag; no external artifact injection point |
| T-04-02-04 | D | docs.yml self-trigger loop from CHANGELOG.md bot commit | mitigate | Two defenses: `[skip ci]` in commit message AND `paths-ignore: ['CHANGELOG.md']` in docs.yml trigger (defense-in-depth — single point of failure if either is removed) |
| T-04-02-05 | I | Workflow logs in public repo | accept | Standard Actions behaviour; no secrets logged (GITHUB_TOKEN auto-masked); environment variables in commit messages would be operator error, not workflow design |
| T-04-02-06 | T | metadata-action tag format | mitigate | Use `type=semver,pattern={{version}}` (verified strips `v` prefix); NOT `type=ref,event=tag` which leaves the `v` (Pitfall 3 — acceptance criteria enforces) |
| T-04-02-07 | D | git-cliff missing tag history on shallow clone | mitigate | `fetch-depth: 0` on checkout step (Pitfall 1); acceptance criteria enforces |
</threat_model>
